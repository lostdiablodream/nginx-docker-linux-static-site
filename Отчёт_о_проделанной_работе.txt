далее, чтобы сайт завёлся из контейнера, нам нужен образ nginx, прокинуть конфиг и каталог с сайтом


конфиг - открываем сервер, ставим ему порт, каталог и как называется файл сайта по умолчанию. убираем кэширование, закрываем сервер.

# nginx.conf
server {
  listen 80;
  root /usr/share/nginx/html;
  index index.html;

  location / {
    add_header Cache-Control "no-store";
    try_files $uri $uri/ =404;
  }
}



образ nginx возьмём готовый. пусть будет на alpine. 
копируем конфиг с заменой файла на который ссылается строка из /etc/nginx/nginx.conf - там должен быть include для *.* из conf.d, но не должно быть ничего того что мы туда не положим. 
копируем сайт в root-каталог из nginx.conf чтобы nginx увидел сайт в контейнере. 
эти копирования нужны если запуск будет из docker run -t -d id_образа без -v folder:folder:ro\rw
открываем порт 80.

# Dockerfile
FROM nginx:stable-alpine

COPY nginx.conf /etc/nginx/conf.d/default.conf

COPY site/ /usr/share/nginx/html/

EXPOSE 80





у нас же запуск будет из композ поэтому создаём композ файл. 
прописываем команду билда и параметры запуска. docker build . собирает образ из докерфайла, находящегося в этом же каталоге. поэтому для build: прописываем только . 
прописываем имя контейнера
пробрасываем порты снаружи внутрь. порты через : пишутся - сначала тот который будет открыт на системе-хосте, затем тот, который будет открыт в контейнере. без проброса порта сетевые обращения будут идти на gateway хоста и за отсутствием открытого порта 80 на системе-хосте, не сможет открыть сайт в системе хосте (при docker exec -it контейнер curl 127.0.0.1:80 мы при этом получим HTTP 200).
пробрасываем ридонли каталог сайта и конфиг. если было бы нужно редактировать сайт и налету его смотреть из nginx в контейнере, то тогда для вольюма с сайтом мы бы ставили rw, и для этого было на всякий случай добавлено add_header Cache-Control "no-store"; в nginx.conf
условие перезагрузки контейнера ставим - до ручной остановки контейнера.

# docker-compose.yml
services:
  web:
    build: .
    container_name: static-web
    ports:
      - "8080:80"
    volumes:
      - ./site:/usr/share/nginx/html:ro
      - ./nginx.conf:/etc/nginx/conf.d/default.conf:ro
    restart: unless-stopped



команда запуска
docker-compose up -d

при выполнении, композ идёт по yaml-шагам, преобразовывая yaml-структуру в команду docker build -t static-web . && docker run -d --name static-web -p 8080:80 -v "$(pwd)/site:/usr/share/nginx/html:ro" -v "$(pwd)/nginx.conf:/etc/nginx/conf.d/default.conf:ro" --restart unless-stopped static-web 

docker-compose down -v останавливает контейнеры и прибирает за собой.





однако, иногда нам может понадобится какая-то конкретная версия nginx, например, последний LTS-релиз

сейчас это 1.31.8, но в разное время может быть разный, поэтому, шаблонизируем через аргумент

ARG UBUNTU_VERSION=24.04
ARG NGINX_VERSION=1.31.8

FROM ubuntu:${UBUNTU_VERSION} AS sources # с алиасом для удобства работы с раздельностью
ARG NGINX_VERSION

# убунту любит спрашивать о всяком, поэтому для автоматики вроде докера для всех debian-like систем ставим
ENV DEBIAN_FRONTEND=noninteractive

# дальше обновляем систему, ставим только гит и СА и чистим apt кэш.
RUN apt-get update \
 && apt-get install -y --no-install-recommends git ca-certificates \
 && rm -rf /var/lib/apt/lists/*

# перемещаемся в каталог для работы с исходниками
WORKDIR /src
# скачиваем последнюю версию nginx
RUN git clone --depth 1 --branch "release-${NGINX_VERSION}" https://github.com/nginx/nginx.git nginx

# та же ос, но теперь алиас для билда
FROM ubuntu:${UBUNTU_VERSION} AS nginx-build
ENV DEBIAN_FRONTEND=noninteractive

# набор компонентов для билда nginx. gcc\g++, make, либы перла для регулярок, функции сжатия и шифрования
RUN apt-get update \
 && apt-get install -y --no-install-recommends build-essential libpcre2-dev zlib1g-dev libssl-dev \
 && rm -rf /var/lib/apt/lists/*

# копируем исходники из образа с исходниками, переходим в каталог
COPY --from=sources /src/nginx /src/nginx
WORKDIR /src/nginx

# configure - команда описывающая билд для make. прописывает пути, участие либ, модулей, префикс.
# make -j указывает количество ядер для распараллеливания компиляции $(nproc) извлекает из среды запуска объём ядер CPU в ОС.
# make install устанавливает в систему результат билда.
RUN auto/configure \
      --prefix=/usr/local/nginx \
      --sbin-path=/usr/sbin/nginx \
      --conf-path=/etc/nginx/nginx.conf \
      --pid-path=/tmp/nginx.pid \
      --with-threads \
      --with-pcre-jit \
      --with-http_ssl_module \
      --with-http_v2_module \
      --with-http_gzip_static_module \
      --with-http_stub_status_module \
 && make -j"$(nproc)" \
 && make install DESTDIR=/out



# рантайм расписываем таким же образом
FROM ubuntu:${UBUNTU_VERSION} AS nginx
ENV DEBIAN_FRONTEND=noninteractive
RUN apt-get update \
 && apt-get install -y --no-install-recommends libpcre2-8-0 libssl3t64 zlib1g curl ca-certificates \
 && rm -rf /var/lib/apt/lists/*
COPY --from=nginx-build /out/ /
COPY nginx/nginx.conf /etc/nginx/nginx.conf
EXPOSE 80

# вместо ENTRYPOINT запускаем глобально как PID 1 - без shell и форков. тогда если получен SIGTERM от docker stop, процесс nginx завершится graceful без осиротевания.
CMD ["nginx", "-g", "daemon off;"]





докер у меня уже был, но если бы не было, то ставил его к себе я бы так:
apt update && sudo apt install -y ca-certificates curl
install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/debian/gpg -o /etc/apt/keyrings/docker.asc
chmod a+r /etc/apt/keyrings/docker.asc
tee /etc/apt/sources.list.d/docker.sources <<EOT
Types: deb
URIs: https://download.docker.com/linux/debian
Suites: $(. /etc/os-release && echo "$VERSION_CODENAME")
Components: stable
Signed-By: /etc/apt/keyrings/docker.asc
EOT
apt update
apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
usermod -aG docker "$USER"
